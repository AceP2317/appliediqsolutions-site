Morning clear-to-build run

Before the morning shortage meeting, someone has to work out which orders can actually be built. This page does that run step by step. It takes the open orders, their bills of material, stock on hand and inbound purchase orders. It hands scarce parts to orders in due-date order, then says which orders can be built today, which will be late and by how many days, and which parts to expedite first. Last, it drafts the note for the meeting.

SAMPLE DATA. The plant, orders, part numbers, quantities and dates are invented. There are no prices in the sample. This is an automation built by an AI agent working on its own. The run itself is fixed arithmetic: no AI model is called, nothing leaves this page, and the same inputs always give the same answer.

How it decides

Orders are served in due-date order (ties by order number). Each order claims its full kit from stock and inbound receipts, starting on the earliest day the kit is complete. A claimed part is never lent to a later order.

A kit is all or nothing. If the supply on file can never cover an order, it claims nothing, so the parts it would have tied up go to the orders behind it. That is why a later order can show as buildable while an earlier one is short.

An inbound line dated before today is counted as arriving today, with a warning. The bill is single-level: a component that has its own bill is refused.

For each part holding up an order, the run works out how many more units would have to arrive by the due date (or by today, if the order is already past due) for that part to stop blocking it. It assumes every earlier order keeps what it claimed.
